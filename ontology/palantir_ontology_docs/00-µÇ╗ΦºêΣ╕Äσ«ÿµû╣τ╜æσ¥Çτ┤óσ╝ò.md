# Palantir Ontology 元素总览与官方网址索引

> 整理日期：2026-09-05  
> 资料范围：Palantir Foundry / Ontology 官方文档。本文为中文归纳，不是对官方文档的逐字翻译。

## 1. 先给结论：Palantir Ontology 有哪些元素？

Palantir 当前官方文档把以下内容明确列为 **Ontology resources（Ontology 一级资源）**：

1. **Object Type**：现实世界实体或事件的模式定义。
2. **Link Type**：两个 Object Type 之间关系的模式定义。
3. **Action Type**：对 Object、Property Value、Link 执行一组业务变更的定义。
4. **Interface**：描述一类 Object Type 的共同形状与能力，用于多态建模。
5. **Shared Property**：可以被多个 Object Type 复用并集中管理元数据的属性。
6. **Object Type Group**：用于对 Object Type 分类、搜索和探索的分组原语。

同时，Palantir 的核心概念文档把 **Property** 作为 Object Type 的关键组成部分；Action Type 内部又由 **Parameters、Rules、Submission Criteria** 等关键结构组成。

此外还有一些与 Ontology 强相关、但不应和一级 Ontology resource 混为一谈的能力：

- **Functions**：代码化业务逻辑，与 Ontology 原生集成，但不是上面官方列表中的一级 Ontology resource。
- **Value Types / Base Types**：用于属性和参数的数据语义、类型和可复用约束。
- **Object / Property Security Policies**：对实例数据和属性值实施行级、列级乃至单元格级控制。
- **Ontology permissions / project-based permissions**：治理 Ontology 资源本身的查看、编辑和管理权限。

## 2. 建议的层级结构

```text
Ontology
├── Object Type
│   ├── Property
│   │   ├── Base Type
│   │   └── Value Type（可选语义约束）
│   └── Shared Property（可复用属性元数据）
├── Link Type
├── Action Type
│   ├── Parameter
│   ├── Rule
│   ├── Submission Criteria
│   └── Side Effects / Webhooks / Notifications
├── Interface
│   ├── Interface Properties
│   ├── Link Type Constraints
│   └── Action Type Constraints
└── Object Type Group

配套能力：
├── Functions
├── Security Policies
└── Permissions / Governance
```

## 4. 对自研 Palantir-style Ontology 平台的建议

如果目标是严格贴近 Palantir，而不是自行发明元模型，建议至少把以下概念作为平台一级能力或明确子结构：

- 一级资源：Object Type、Link Type、Action Type、Interface、Shared Property、Object Type Group。
- Object Type 子结构：Property、Primary Key、Title Key、Backing Datasource、Metadata。
- Link Type 子结构：Source/Target Object Type、Cardinality、Side API Names、Metadata。
- Action Type 子结构：Parameters、Rules、Submission Criteria、Side Effects。
- Interface 子结构：Interface Properties、Link Type Constraints、Action Type Constraints、Interface Inheritance / Implementation。
- 类型系统：Base Types、Value Types。
- 治理：Resource permissions、Object/Property security policies、Status、Version/compatibility considerations。

这样既能覆盖 Palantir 的核心建模结构，也为后续 Runtime、SDK、Actions 和权限系统留出一致的扩展空间。
